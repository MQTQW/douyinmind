# 对话编排候选实现

[助手使用说明](抖音助手使用说明.md) · [技术结构](architecture.md)

本文说明当前开发代码的能力边界。代码存在、合成测试通过和真实平台验收是不同的证据；本能力不默认启用。

## 分阶段范围

| 阶段 | 当前代码提供的部分 | 仍需完成的部分 |
| --- | --- | --- |
| 第一版 | 显式启用后的意图澄清会话；经原线程核验的补充回复；明确保存或转入正式选库；原生收件挂起原因的独立显示 | 实际平台新增请求验收、完整发布和回退验收 |
| 第二版 | 工作流状态库与单步协调器；保存、等待、检索、回复草稿的有限计划；请求去重、租期和累计模型 token 预算约束 | 与真实收件、入库、Agent 和发表链路的适配 |
| 第三版 | 有限计划白名单、修订范围和权限检查接口 | 模型规划入口、规划调用本身的预算预留、更多会话类型及真实验收 |

第二、三版的内部模块尚未接入普通 @B 请求。不能据此宣称“保存后自动总结”或任意连续对话已经可用。

## 第一版处理范围

仅原始语义结果为 `semantic_intent_unclear` 的新请求可以建立意图澄清会话。无原文、无权限、服务失败等其它澄清不会因此获得保存能力。

一次补充回复必须重新核对同一 A/B、视频、原始真正 @、精确 B 澄清回执、唯一当前回复和当前权限。它使用独立的 `intent_clarification_reply` 证据及语义回执，不能冒充真正 @，也不放宽普通资料追问的只读动作范围。

补充回复明确保存后：

- 目标为唯一获准库时，创建唯一保存子任务。
- 缺少目标库时，创建正式选库菜单，再复用原选库保存流程。
- 目标歧义、权限变化或实际页面无法核实时，保留状态和原因，不猜默认库，不静默扩大资料范围。

新菜单同时保留原始 @ Root、当前补充回复和菜单任务三层关系。正式选库子任务的来源授权必须核对这三层，不能仅通过一个父评论编号提示就执行。

这一版解决一次意图补全后的保存路径，不代表所有澄清都能无限多轮承接，也不保证模型首次分类不出错。

## 配置与停用

以下命令仅用于已经完成本机助手配置、且加载匹配代码版本的环境。在 `backend` 目录执行：

```powershell
uv run python -m app.assistant --enable-intent-clarification
```

启用命令只配置本能力，记录首次激活时间，不启动 B、不创建第二个后台 owner，也不回填旧任务。之后是否开启 B，仍由正常产品入口明确决定。

候选代码的无损停用入口为：

```powershell
uv run python -m app.assistant --disable-intent-clarification
```

停用只阻止新的澄清续接动作，不撤回已经提交的入库或评论。它保留原激活时间、会话、来源、费用和发送记录；重新启用不清除旧屏障，也不把旧挂起来源自动重放。缺少该能力的台账时，停用不创建零字节库或新 owner。

不要通过删除数据库、保护标记、修改激活时间或换回旧源码来模拟停用。旧版本对新证据类型的兼容性需要单独验证，不能承诺任意代码回退都安全。

## 中断与未知结果

多个台账之间发生中断时，只能依据已经存在且精确对应的记录修复会话关联。例如任务已登记、来源已确认入队，而会话尚未记下子任务，恢复只能关联这个已有任务。

B 回读结果已经落账时，可以将这个已有事实投影回新会话；不能为补状态再次生成模型答案、创建任务或发表评论。已识别的执行、发送预约或未知结果冲突会保守停止；不同恢复入口的元数据一致性、分页和异常局部化仍有待完善，见 [开发交接](handoff-2026-10-30.md#首先要补齐的恢复边界)。不能宣称所有异常都已转为单会话需要核对。

收件页面中的“需核对记录”独立于授权配置问题和任务队列。看到通知不等于已受理，无队列任务也不能普遍推断没有发生模型费用。

## 内部工作流接口

`workflow_store.py` 与 `workflow_engine.py` 是第二、三版基础：

- 构造不自动打开真实资料、模型或浏览器；实际工具和授权器由调用方注入。
- 每次推进至多执行一个步骤，等待阶段只查询原入库回执。
- 工具执行前先预留步骤和预算；工具适配器还须在实际副作用门前调用 checkpoint。
- 用量须与请求键、视频和知识库对应；错误范围中的零用量不能释放本步骤预算。
- 修改计划需要独立的新用户补充证据，当前只允许削减既有动作，不新增保存或查询能力。
- 草稿准备好仅为 `proposal_ready`；实际 B 回读由既有发表链路证明后才可完成。

这些约束需要真实适配器共同遵守，不能把注入一个始终返回 True 的假授权器当成生产授权。

## 验证

新增合成测试覆盖澄清会话、实际来源授权组合、选库子任务、预算前置上下文、中断窗口、停用、重启及错误范围拒绝；工作流测试覆盖租期、计划修订和未知费用。

测试使用合成账号、视频、评论和临时台账。真实用户资料、登录会话、费用历史和实际截图不属于公开测试夹具。真实验收必须另外记录，不能把模拟结果计作实际收件或评论送达。
