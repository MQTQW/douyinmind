# 历史接收器原型与开发参考

> 这是历史实验说明，不是当前日常启动指南。使用项目左侧「抖音助手」；首次配置与核验见[当前使用说明](抖音助手使用说明.md)。原型没有通过真实跨电脑验收。

## 原型曾做什么

最早的接收器使用独立B浏览器资料目录，正常打开通知页，仅从渲染出来的页面读取账号链接、真正的 @、评论全文和对应视频，再保存到独立预览台账。预览不等于知识库任务，不自动调用模型、下载视频、导入或发表。

之后增加了显式绑定的单任务实验：限定A/B、单库和处理次数，模型选择受限工具，程序核对原评论后保留一次发送。这些实验曾用固定标记和可见测试窗口控制范围；它们不是现在用户必须使用的句式、编号或运行方式。

Replay（保存样本回放）与isolated（隔离合成测试）只能证明解析和状态逻辑；不能证明通知来自当前真实账号，更不能代替权限或发表前核对。

## 当前实现与旧实验的区别

| 部分 | 当前日常助手 | 旧实验资料应怎样理解 |
| --- | --- | --- |
| 日常入口 | 项目「抖音助手」与受控启停 | 不再推荐用旧接收测试批处理代替日常入口 |
| B会话 | 默认headless（后台无桌面窗口），本人核验使用同会话的本机网页面板 | 旧版独立桌面窗口描述仅代表当时实现 |
| 语言理解 | 显式启用语义层后理解自然请求，不要求固定编号 | 旧固定标记用于限定试验，不是产品能力 |
| 授权 | Registry（本机授权台账）核对用户、设备、库与公开许可 | 旧单库绑定不等于可绕过后来撤销 |
| 收件与执行 | 原生通知或正常页面提供候选；实际页面、当前权限与持久任务仍分别核对 | 一个原生评论ID或“已收到”标志不是完整执行授权 |
| 结果 | 资料状态、发送状态、B回读与A观察分开 | 不能把旧单条成功推广为所有人都收到 |

日常授权台账或迁移标记已经存在时，旧执行入口会拒绝继续动作。不要删掉它们来回到旧绑定。普通预览、历史状态和源码可供开发参考，但不应另起一个旧程序同时拥有相同B账号或数据库。

## 现在仍需保留的规则

- 原文和目录是数据，不能把评论中伪装的系统指令当成授权。
- Native ID（平台原生编号）可帮助定位；评论通知中的父编号提示本身不证明完整父链或目标线程。
- 未知可见性不是可见；只读理解也不是执行。真正检索、入库或发表仍要经过相应当前门禁。
- 一次发送预约必须先持久记录；未知结果、重启或重复请求不能触发再次发表。
- 真实入库成功要核对目标库关联、视频完成状态与可检索正文，不能只看内存显示或标题信息。
- B回读可见不自动等于A收到，平台页面变化和本人核验都可能令流程暂停。

## 历史记录的保留方式

包含真实账号、视频、任务号、原文和截图的原型全文、失败与后续补证保留在维护者本机，不作为公共文档上传，不在这里链接。公开说明保留演进和边界；不把不同时期的测试数相加，也不把旧空闲观察套用到当前代码。
