## 正常 enable / disable 契约

以下只描述已经完成本机助手准备、加载匹配版本后的产品契约；不要在新电脑上为“试一下”直接执行。

```powershell
# 在 backend 目录，显式配置未来的 v1 续接能力
uv run python -m app.assistant --enable-intent-clarification

# 无损撤销新的 v1 续接动作
uv run python -m app.assistant --disable-intent-clarification
```

- `enable` 只配置能力并保留首次 `activated_at`；不启动 B、不创建第二个后台 owner、不改判旧付费回执、不回填旧 Root 或来源。
- 运行时协调器在 owner 启动接线时安装。配置命令不热更新现有 owner；对未安装协调器的旧进程，仅点“开启”不会重新构造它。需要加载匹配代码时走正常停止、等待结束、再启动流程。
- `disable` 可在登录或 Registry 配置异常时撤销能力，不要求先启动 B；能力台账及标记都不存在时，不创建空数据库、Queue、Control 或新 owner。
- 停用保留首次激活时间、会话、来源、费用、已提交的入库和发送记录；不等于撤销已经发生的外部操作。
- 已装入协调器的路径会重新读取启用状态。并发停用应局限于本次澄清续接，不应将普通 @ 或其它来源改成全局停止或自动重放。
- 重新启用不产生新激活周期，不清除旧 claim、held、费用或发送屏障。不要删台账、改时间或换回旧源码模拟停用。
- 旧代码对新证据类型的兼容性尚需单独验证，不能保证任意代码回退都安全。

## 恢复契约：补关联，不重放

`recover_links` 仅处理已经计划的新证据类型，不为旧 Root 重新 arm。`reconcile_existing` 只读取已存在的 v1 会话及精确对应的持久记录：

- 可以将已经落账的 B 可见事实投影回会话，不重新生成答案或再发表评论。
- 来源已确认 admitted、Queue 已有精确匹配任务，但会话关联未落账时，只关联这个已有任务；来源仍 planned 的窗口交原 Source 恢复流程处理。
- 补 planned 关联时，已有 Agent 工作、发送预约、未知结果或权限不一致就需要核对；不能因补会话状态而获得新执行或发表能力。已经落账的 B 可见事实只按前述只读投影处理。
- 停用时可记录已经存在的可见事实，但不能用它启动新续接动作。
- 历史来源、旧 Root、held 来源及过期/不明确状态不能自动恢复成 fresh。无 Queue 任务也不能普遍推断没有模型费用。
